# Prawdoskop: raport z 22 listopada 2026

Zakres: kanał urzędowy z przebiegiem moderatorskim, rozbudowa korpusu o 400 materiałów z pomiarami, EUvsDisinfo, prezentacja i wdrożenie. Oznaczenia: **[sprawdzone]** — zweryfikowane w tej sesji żądaniem lub testem; **[niesprawdzone]** — wniosek bez bezpośredniej weryfikacji.

## 1. Trzy kanały urzędowe

| | IMGW: ostrzeżenia meteo | RCB: komunikaty i Alert RCB | RSO: Regionalny System Ostrzegania |
|---|---|---|---|
| Działający adres | `https://danepubliczne.imgw.pl/api/data/warningsmeteo` (też `warningshydro`) — HTTP 200 **[sprawdzone]** | `https://www.gov.pl/web/rcb/komunikaty` — HTTP 200, HTML **[sprawdzone]**. RSS archiwum `archiwum.rcb.gov.pl/feed/` działa, ale ostatni wpis jest z 2022 **[sprawdzone]** | `https://komunikaty.tvp.pl/komunikaty/wszystkie/wszystkie/0?_format=json` (też `_format=xml`) — HTTP 200 **[sprawdzone]**. `rso.gov.pl` nie odpowiada **[sprawdzone]** |
| Format | JSON, lista ostrzeżeń: `id`, `nazwa_zdarzenia`, `stopien`, `prawdopodobienstwo`, `tresc`, `biuro`, `teryt` (kody powiatów) **[sprawdzone]** | strona HTML; lista z datą `dd.mm.rrrr`, artykuł z `p.event-date` i `.editor-content` **[sprawdzone]**; brak API i RSS **[sprawdzone dla /rss]** | JSON i XML: `id`, `title`, `content`, `valid_from/to`, `created_at`, `updated_at`, `provinces` (województwa), `rso_alarm` **[sprawdzone]** |
| Wymagania dostępu | bez klucza; `cache-control: no-store` **[sprawdzone]** | bez klucza **[sprawdzone]** | bez klucza; `cache-control: max-age=120` **[sprawdzone]** |
| Data publikacji i ważności | `opublikowano`, `obowiazuje_od`, `obowiazuje_do` (czas lokalny) **[sprawdzone]** | data publikacji na liście i w artykule; ważności brak (treść alertu) **[sprawdzone]** | `created_at`, `valid_from`, `valid_to` **[sprawdzone]** |
| Korekty | brak pola wersji. Prawdoskop wyznacza wersję po skrócie treści, ważności i obszaru **[sprawdzone w teście]**. Czy IMGW zmienia `id` przy korekcie: **[niesprawdzone]** | publikacja nowego komunikatu, np. „Aktualizacja…” w GIS; RCB bez znacznika aktualizacji **[sprawdzone na listach]** | pole `updated_at`; 62 z 95 wpisów miało `updated_at ≠ created_at` **[sprawdzone]** |
| Ponowne użycie | regulamin IMGW-PIB: bezpłatnie, z dopiskiem „Źródłem pochodzenia danych jest IMGW-PIB” i informacją o przetworzeniu **[sprawdzone, apiinfo]** | treści tekstowe Gov.pl: CC BY-SA 4.0 **[sprawdzone, gov.pl/web/gov/warunki-korzystania]** | regulamin serwisu komunikaty.tvp.pl nie znaleziony (`/regulamin` → 404) **[niesprawdzone]** |

**Wybór do prototypu: IMGW.** Stabilne API JSON bez klucza, jawne daty publikacji i ważności, a przede wszystkim kody TERYT powiatów. Dzięki nim zgłoszenie da się dopasować do konkretnego powiatu i dnia. RSO jest następny w kolejce: ma `updated_at`, ale obszar tylko na poziomie województwa. RCB wymaga parsera HTML.

## 2. Import przyrostowy i przebieg moderatorski

Kod: [app/ingest/imgw.py](../app/ingest/imgw.py), [app/ingest/official.py](../app/ingest/official.py), [app/storage/official.py](../app/storage/official.py), panel [app/templates/moderacja.html](../app/templates/moderacja.html).

1. Pobranie listy (co `PRAWDOWID_OFFICIAL_POLL_S` s, na Fly.io 600 s, gdy maszyna działa; ręcznie przyciskiem „Pobierz teraz” lub `POST /api/v1/official/sync`).
2. Dla każdego wpisu porównanie skrótu SHA-256 z ostatnią wersją. Bez zmian: tylko `last_seen_at`. Nowy lub zmieniony: nowa wersja w `official_entries` (data publikacji, czas pobrania, czas indeksacji, numer wersji) i w indeksie wyszukiwania. Poprzednia wersja wypada z wyszukiwania.
3. Ponowna ocena tylko **otwartych** spraw, których dotyczy wpis (to samo zjawisko, wspólny kod TERYT, dzień w okresie ważności), istniejącym `Service.run` z wpisem przypiętym do kandydatów.
4. Propozycja dla moderatora: poprzedni wynik, proponowany wynik, cytat z nowego wpisu. Zatwierdzenie zamyka sprawę. Ponowny import tego samego wpisu nie tworzy wersji, propozycji ani dokumentów (`UNIQUE(case_id, source_id)`).

**Sprawy.** Zgłoszenie z rozpoznanym zjawiskiem i powiatem trafia do sprawy o kluczu `zjawisko|TERYT|dzień` ([app/ingest/places.py](../app/ingest/places.py), słownik 380 powiatów z zestawu MEN na dane.gov.pl). Sprawa ma licznik zgłoszeń i opis brakującego dowodu.

**Demo do odtworzenia:** `python scripts/demo_moderacja.py` (bez kosztów) lub `--live` (prawdziwy model). Test od początku do końca: [tests/test_official.py](../tests/test_official.py).

| Krok demo | Wynik (ewaluator demonstracyjny i live) |
|---|---|
| 2 różnie sformułowane wiadomości o gołoledzi, pow. bytowski, 3.12.2026 (WWW + adapter) | 1 sprawa, licznik 2, opis brakującego dowodu |
| ta sama treść dla pow. chojnickiego / dla 4.12.2026 | 2 osobne sprawy |
| import komunikatu bez związku (wiatr, Słupsk) | 1 nowy wpis, 0 propozycji |
| import ostrzeżenia o oblodzeniu (pow. bytowski i słupski, 3.12) | propozycja tylko w sprawie bytowskiej z 3.12: live `not_verifiable → confirmed`, cytat „Prognozuje się zamarzanie mokrej nawierzchni dróg i chodników po opadach deszczu ze śniegiem.” |
| powtórny import | 0 nowych, 2 bez zmian, 0 propozycji, liczba dokumentów bez zmian |
| korekta IMGW (przedłużenie do 14:00) | wersja 2, stara wersja usunięta z indeksu, nowa propozycja |

**Pomiar czasu publikacja → Prawdoskop.** Opóźnienie liczymy jako `indexed_at − opublikowano` dla wpisów, które pojawiły się po pierwszym pobraniu (wpisy z pierwszego pobrania to zaległość). Skrypt: `python scripts/measure_imgw_lag.py --interval 120 --duration 10800`. Wynik w [eval/imgw_lag.json](../eval/imgw_lag.json): 23 pobrania co 2 minuty od 00:18 do 01:02 UTC, 0 błędów, mediana importu 132 ms. W tym oknie IMGW nie opublikował nowego ostrzeżenia, więc **opóźnienia na świeżym wpisie nie zmierzono**. Górna granica wynika z konfiguracji: interwał odpytywania (600 s na Fly.io) + import (932 ms na produkcji). Panel pokazuje medianę, gdy pojawią się pomiary.

**Nieudana synchronizacja.** Każdy przebieg trafia do `sync_runs` ze stanem i treścią błędu, a zdarzenie `official_sync_failed` do dziennika. Panel moderatora pokazuje komunikat „Synchronizacja IMGW nie powiodła się…” z godziną, treścią błędu i czasem ostatniego udanego pobrania. Po 30 minutach bez udanego pobrania pokazuje „Komunikaty IMGW mogą być nieaktualne”. `/health` zwraca `official_feed.failing`, `stale` i `last_error`. Test: `test_failed_sync_is_reported`.

## 3. Rozbudowa korpusu

Skrypt [scripts/collect_corpus.py](../scripts/collect_corpus.py) pobiera strony, zapisuje wydawcę, adres, datę publikacji (i aktualizacji, gdy jest), dosłowne akapity i warunki użycia. Odrzuca stronę bez daty, tytułu lub akapitu, fragment niezgodny z treścią strony, duplikat adresu lub tytułu oraz wiadomości samorządowe spoza tematu usług publicznych i ostrzeżeń.

**Przyjęto 400 rekordów** ([Research/Prawdoskop_Korpus_Rozszerzenie_400.jsonl](../Research/Prawdoskop_Korpus_Rozszerzenie_400.jsonl)); korpus v5 ma 513 dokumentów i 16 domen.

**Warunki użycia:** gov.pl CC BY-SA 4.0 **[sprawdzone]**. Samorządy: krótki cytat z linkiem; komunikaty urzędowe nie są przedmiotem prawa autorskiego (art. 4 pkt 2), regulaminów serwisów nie sprawdzano. Fact-checki: prawo cytatu z linkiem; licencji wydawców nie sprawdzano.

**Luki:**
- RSO i RCB nie są jeszcze importowane automatycznie; RCB ma 20 komunikatów z ostatnich tygodni.

- ZUS, NFZ, pacjent.gov.pl, policja.gov.pl — nie objęte tą partią.
- AFP Sprawdzam blokuje pobieranie (HTTP 403); Konkret24 wymaga osobnego parsera.
- Fragment to zwykle pierwsze akapity; przy części wiadomości urzędów wojewódzkich dotyczą wydarzeń, nie usług.
- Gdańsk i Łódź: mało rekordów; Rzeszów zwrócił 503, Białystok bez dat.

## 4. EUvsDisinfo

**MCP:** serwer `https://euvsdisinfo-mcp-server.vercel.app/mcp` (streamable HTTP, narzędzia `cases`, `articles`, według dokumentacji przekazanej na Discordzie) odpowiada `401 Unauthorized: API key required` **[sprawdzone]**. Tokenu nie ma w projekcie, więc **przebiegu przez MCP nie sprawdzono**. Klient jest gotowy: [app/ingest/narratives.py](../app/ingest/narratives.py) `fetch_cases()` z `PRAWDOWID_EUVS_TOKEN`. Strony przypadków blokują automatyczne pobieranie (403); przypadek odczytano w przeglądarce.

**Przykład:** narracja „Polska chce zająć zachodnią Ukrainę”. Przypadek [poland-wants-to-seize-western-ukraine-and-western-belarus](https://euvsdisinfo.eu/report/poland-wants-to-seize-western-ukraine-and-western-belarus/) z 4.10.2024 oraz 4 wcześniejsze z 2022 r. (lista: [Research/EUvsDisinfo_Przypadki.jsonl](../Research/EUvsDisinfo_Przypadki.jsonl)).

Zgłoszenie testowe: „PILNE: 21.11.2026 Polska wkroczy na zachodnią Ukrainę i zajmie Lwów. Podpisano: Sztab Generalny Wojska Polskiego”.
- Wspólne: teza o zajęciu zachodniej Ukrainy przez Polskę.
- Różnice: nowa data (21.11.2026 zamiast 2024), konkretne miejsce (Lwów), podpis (Sztab Generalny WP zamiast wypowiedzi przypisanej stronie białoruskiej w portalu livenews.am i na Telegramie).
- Wynik na produkcji (live): werdykt „Nie wiadomo” / „nie podlega weryfikacji” z brakującym dowodem (komunikat MON lub DO RSZ), plus uwaga „znana narracja” z linkiem. Podobieństwo nie zmienia werdyktu. Zapis: [eval/euvsdisinfo_przyklad.json](../eval/euvsdisinfo_przyklad.json), test [tests/test_narratives.py](../tests/test_narratives.py).

## 7. Braki

- Opóźnienie publikacja → Prawdoskop nie zostało zmierzone na nowym wpisie IMGW (brak nowych ostrzeżeń w oknie pomiaru).
- Przebieg EUvsDisinfo przez MCP nie został uruchomiony (brak tokenu).
- Na Fly.io import działa tylko, gdy maszyna jest uruchomiona (auto-stop). Stałe odpytywanie wymaga harmonogramu albo `min_machines_running = 1`, co zmienia koszt.
- Rozpoznawanie powiatów: wielowyrazowe nazwy miast (np. Zielona Góra, Bielsko-Biała w odmianie) nie są rozpoznawane.
- Strażnik liczb potrafi usunąć całe uzasadnienie („Szczegóły podajemy w cytacie…”), gdy model poda godzinę spoza cytatu.
- Sprawy przechowują zamaskowaną treść zgłoszeń bez osobnej retencji (sprawdzenia mają 7 dni).
